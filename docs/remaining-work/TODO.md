# งานที่เหลือ เอาไปแบ่งกันทำได้เลย

ตอนนี้มีหน้าเว็บแล้ว ลูกค้ากับออเดอร์เริ่มดึง API และแสดงหมุดได้ แต่ส่วนจัดเส้นทางกับใบงานไรเดอร์ยังใช้ข้อมูลตัวอย่างอยู่ งานหลักที่ต้องทำต่อมีตามนี้

## 1 หน้าลูกค้า

- [ ] แก้ให้เปลี่ยนพิกัดแล้วหมุดย้ายตามทันที ตอนนี้บันทึกข้อมูลแล้วหมุดยังค้างที่เดิม
- [ ] ลูกค้าที่ไม่มีพิกัด อย่าเติมเป็น 0 0 ให้อัตโนมัติ
- [ ] ตรวจข้อมูลก่อนบันทึก และลองว่าบันทึกแล้วเปิดหน้าใหม่ยังได้ข้อมูลที่แก้

ดูที่ `customer.ts`, `customer.service.ts` และ `customer-detail-panel.ts`

## 2 หน้าออเดอร์

- [ ] ทำปุ่ม + ให้เพิ่มออเดอร์ได้จริง
- [ ] ทำแก้ไขจำนวนแล้วกดบันทึกได้ ตอนนี้มีช่องให้แก้ แต่ยังไม่มีคำสั่งบันทึก
- [ ] เพิ่มลบหรือยกเลิกออเดอร์
- [ ] ทำช่องค้นหาให้ใช้งานได้ และเลือกออเดอร์ตามวันส่ง
- [ ] บังคับจำนวน 1 ถึง 3 กล่องต่อออเดอร์ แล้วอัปเดตหมุดให้ตรงกับจำนวนที่แก้
- [ ] ลองปุ่มจำลองให้ได้ชุด 20 ถึง 30 ออเดอร์ และมีข้อความบอกเมื่อโหลดหรือสร้างข้อมูลไม่สำเร็จ

ดูที่ `order.ts`, `order.html`, `order-detail-panel.ts` และ `order-selection.service.ts`

## 3 ระบบแบ่งงานและคำนวณเส้นทาง

**ส่วนนี้เป็นงานหลักของโปรเจกต์ และยังไม่พบโค้ดคำนวณจริงใน repo นี้**

- [ ] เอาออเดอร์จริงของวันนั้นมาจัดกลุ่ม ให้ไรเดอร์คนละไม่เกิน 3 ออเดอร์ ทุกออเดอร์ต้องถูกจัดครั้งเดียว
- [ ] กำหนดพิกัดร้าน แล้วคำนวณระยะทางและลำดับจุดส่งให้แต่ละคน
- [ ] คำนวณเวลาจากความเร็วประมาณ 30 กม./ชม. เริ่ม 11.30 น. ทุกจุดต้องถึงไม่เกิน 12.30 น.
- [ ] เลือกแผนที่ประหยัดและทันเวลา พร้อมให้คำนวณใหม่หรือเลือกแผนอื่นได้
- [ ] ถ้าพิกัดไม่ครบหรือจัดให้ทันไม่ได้ ต้องบอกว่าออเดอร์ไหนมีปัญหา

ตอนนี้ `route.ts` เป็นรายการงานตัวอย่าง ส่วน `route.service.ts` มีแค่ตัวแปรสลับยืนยัน ต้องเพิ่มส่วนคำนวณและเชื่อม backend

จำไว้ว่า **3 ออเดอร์ต่อไรเดอร์ ไม่ใช่ 3 กล่อง** เช่น 3 ออเดอร์ ออเดอร์ละ 3 กล่อง รวม 9 กล่องก็ยังอยู่ในเงื่อนไข

## 4 ค่าส่งและกำไร

- [ ] คิดรายได้จากกล่องละ 65 บาท และต้นทุนอาหารกล่องละ 40 บาท
- [ ] รวมค่าเรียกไรเดอร์ 15 บาทต่อครั้ง และค่าเดินทาง 2 บาทต่อกม.ต่อกล่อง
- [ ] แสดงค่าส่งกับกำไรสุทธิจริง ทั้งรายงานของไรเดอร์แต่ละคนและยอดรวมของแผน
- [ ] แก้ข้อความกำไรต่อกล่องในหน้าออเดอร์ ตอนนี้สูตรคูณจำนวนกล่องแล้ว แต่ชื่อยังเขียนว่าต่อกล่อง

สูตรที่เสนอคือ `ค่าส่ง = 15 + 2 × จำนวนกล่องทั้งงาน × ระยะทางทั้งงาน` เช่น 6 กล่อง 2 กม. ค่าส่งรวม 39 บาท กำไรสุทธิ 111 บาท แต่ควรเช็กกับอาจารย์ก่อน เพราะข้อความตัวอย่างในโจทย์กำกวม และยังไม่ได้บอกว่าคิดระยะขากลับร้านด้วยไหม

ดูที่ getter `profit` ใน `order-detail-panel.ts` ส่วนตัวเลขใน `route-detail-page.html` ยังเป็นค่าคงที่

## 5 หน้าจัดเส้นทางของเจ้าของร้าน

- [ ] ทำปุ่มคำนวณให้เรียกส่วนคำนวณจริง แล้วเอาผลมาแสดงแทนข้อมูลตัวอย่าง
- [ ] เพิ่มแผนที่ใหญ่ วาดเส้นทางไรเดอร์แต่ละคนคนละสี พร้อมลำดับจุดส่ง
- [ ] กดเลือกงานแล้วแสดงเส้นทาง จำนวนกล่อง ระยะทาง เวลาและกำไรของงานนั้น
- [ ] ทำปุ่มคำนวณใหม่ให้กดได้จริง
- [ ] กดยืนยันแล้วบันทึกแผนและสร้างเลขใบงานจริง เปิดหน้าใหม่แล้วยังอ่านแผนเดิมได้
- [ ] เอาข้อความทดลอง `bus` กับ `zzzzzzz` และตัวเลขตัวอย่างออกเมื่อเชื่อมข้อมูลแล้ว

ดูที่ `route.ts`, `route.html`, `route.service.ts` และ `route-detail-page.html`

## 6 หน้าไรเดอร์

- [ ] กรอกเลขใบงานแล้วดึงงานของเลขนั้นจาก API ตอนนี้ทุกเลขยังเปิดข้อมูลตัวอย่างชุดเดียวกัน
- [ ] เลขว่างหรือเลขที่ไม่มีจริง ต้องบอกว่าไม่พบงาน
- [ ] แสดงวันที่ จำนวนกล่องรวมและลำดับจุดส่งให้ตรงกับแผนที่เจ้าของยืนยัน
- [ ] ปุ่มดูตำแหน่งต้องเปิดแผนที่ไปยังพิกัดลูกค้าจริง ตอนนี้เปิดได้แค่กล่องข้อความ
- [ ] ถ้าจะใช้ปุ่มรับอาหารและส่งเสร็จที่ทำไว้ ให้บันทึกสถานะลง server ด้วย ไม่ให้หายเมื่อรีเฟรช

ดูที่ `work-num-form.ts`, `driver-gui.ts`, `driver-gui.html` และ `rider-work.ts`

## 7 Backend และฐานข้อมูล

มี API ที่ frontend เรียกใช้อยู่แล้ว แต่ repo นี้ไม่มีโค้ด backend ให้ตรวจ ต้องไปดูของเดิมก่อนว่าอะไรทำไว้แล้วบ้าง

- [ ] เช็ก API เพิ่ม แก้ ลบลูกค้าและออเดอร์ แล้วทำเฉพาะส่วนที่ยังขาด
- [ ] เพิ่ม API คำนวณแผน ยืนยันแผน และค้นใบงานตามเลข
- [ ] บันทึกแผน ลำดับจุดส่ง ระยะทาง เวลาและต้นทุนลงฐานข้อมูล
- [ ] ป้องกันกดยืนยันซ้ำแล้วสร้างใบงานซ้ำ และอย่าให้ยืนยันแผนเก่าหลังออเดอร์เปลี่ยน

คุยชื่อช่องข้อมูลและรูปแบบ API กับคนทำหน้าเว็บก่อน จะได้ต่อกันได้

## 8 ลองระบบรวมและเตรียมส่ง

- [ ] ลองตั้งแต่เพิ่มลูกค้า สร้างออเดอร์ คำนวณ ยืนยัน แล้วเอาเลขใบงานไปเปิดหน้าไรเดอร์
- [ ] ลองทั้ง 20 และ 30 ออเดอร์ เช็กว่าไม่มีตกหล่นหรือซ้ำ และทุกคนไม่เกิน 3 ออเดอร์
- [ ] ลองเปิดหน้าไรเดอร์บนมือถือ และกดลิงก์แผนที่ทุกจุด
- [ ] แก้ทางเข้าหน้าเจ้าของ ตอนนี้ใช้ key ที่ฝังใน frontend และเปิด URL เจ้าของได้ตรงๆ
- [ ] ลอง production build ใหม่ ตอนตรวจติดการดาวน์โหลด Google Fonts ส่วน development build กับ tests เดิม 9 รายการผ่านแล้ว
- [ ] ตอนขึ้น server ตั้ง `/api` ให้ไป backend และลองรีเฟรช URL หน้าย่อยให้เปิดได้

## เริ่มทำอะไรก่อน

เช็ก API ที่ขาดก่อน แล้วแบ่งคนทำหน้าลูกค้ากับออเดอร์ อีกคนเริ่มส่วนคำนวณเส้นทางและค่าส่ง พอได้ผลคำนวณค่อยต่อหน้าเจ้าของและใบงานไรเดอร์ สุดท้ายค่อยลองระบบรวม

ถ้าต้องตัดงานให้ทันส่ง ให้เน้น **คำนวณเส้นทางจริง แสดงเวลาและกำไรจริง และเปิดใบงานจริง** ก่อน ส่วนเพิ่มลบลูกค้าให้เช็กขอบเขตกับอาจารย์ เพราะโจทย์เขียนรวมๆ ว่าจัดการข้อมูลลูกค้า และไม่ต้องเพิ่ม GPS ติดตามสดหรือระบบชำระเงินเพื่อให้ครบโจทย์
